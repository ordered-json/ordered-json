# 저장소 계약

[English](repositories.md)

<a id="ownership"></a>
## 관리 주체

공통 저장소는 JSON 명세, 공식 입력과 기대 결과, 공통 검증기, 구현 등록 정보, 통합 검증 기록을 관리합니다. 각 구현 저장소는 소스, 어댑터, 패키지 메타데이터, 문서, 릴리스 절차를 관리합니다.

| 저장소 | 체크아웃 경로 | 구현 |
| --- | --- | --- |
| ordered-json/ordered-json | . | 공통 계약과 검증 |
| ordered-json/javascript | js | JavaScript |
| ordered-json/rust | rust | Rust |
| ordered-json/go | go | Go |
| ordered-json/php | php | 순수 PHP와 PHP Value API |
| ordered-json/php-extension | php-extension | 네이티브 PHP 확장 |

공통 저장소는 구현의 정확한 커밋을 Git 서브모듈로 기록합니다. 구현 저장소는 공통 저장소를 역방향 서브모듈로 포함하지 않습니다. 순수 PHP와 확장은 소스 및 릴리스 이력을 별도로 관리합니다. 네이티브 구현은 명시적으로 선택한 PHP Value API 개정본과 함께 검사합니다.

<a id="verification"></a>
## 공통 검증

공식 입력과 기대 결과는 공통 저장소에만 존재합니다. 어댑터는 공통 보고 형식을 반환하며 독립 기대값을 포함하지 않습니다. 구현 등록 정보는 저장소 위치, 어댑터 명령, 빌드 명령, 런타임 버전 명령을 정의합니다. 언어 추가에 JSON 비교 알고리즘 변경이 필요해서는 안 됩니다.

구현의 단독 검사는 적합성 설정에 기록된 전체 커밋의 공통 검증기를 가져와 현재 로컬 구현 체크아웃을 검사합니다. 필요한 테스트 의존성도 전체 커밋 ID를 사용합니다. 공동 개발을 위해 로컬 검증기를 명시적으로 지정할 수 있습니다. 테스트 보고서는 검증기 소스, 구현 소스, 의존성 개정본, 런타임, 결과를 명시합니다.

통합 검사는 체크아웃된 서브모듈 커밋으로 등록된 모든 구현을 검사합니다. 통합 결과를 기록할 때 고정된 서브모듈이 없거나 수정됐다면 거부합니다. 구현 PR은 후보 소스에 공통 검사를 실행해야 하며 통합 결과는 기록된 조합에만 적용됩니다.

<a id="documents"></a>
## 문서와 변경

각 저장소는 자체 영어 문서와 한국어 번역을 등록합니다. 구현 문서는 공통 계약과 통합 기능 상태를 참조합니다. 공통 문서 검사는 초기화된 구현 저장소의 문서도 검사합니다.

공통 계약을 변경할 때 검증기 개정본을 게시하고, 관련 구현과 적합성 개정본을 갱신하고, 후보 검사를 실행한 다음 공통 저장소의 서브모듈 커밋을 갱신하고 통합 검사를 실행합니다. 테스트 성공과 소스 또는 패키지 게시는 별도로 확인합니다.

<a id="php-extension"></a>
## PHP 확장 패키지

PHP 라이브러리는 `ordered-json/ordered-json` Composer 패키지를 사용합니다. 확장은 별도 PIE 패키지 `ordered-json/ordered-json-extension`, `php-ext` 유형, `ordered_json` 확장 이름, `src` 빌드 경로를 사용합니다. 설정은 단독 확장 빌드를 기본으로 활성화합니다. PHP 라이브러리는 테스트 의존성이며 네이티브 빌드나 PIE 패키지 의존성이 아닙니다.

PIE 호환성을 기록하기 전에 PIE 패키지 검사와 로컬 PIE 빌드가 성공해야 합니다. 로컬 빌드는 Packagist 게시, 릴리스된 버전, Windows 바이너리 제공, 사용자 PHP 설정에 설치했다는 근거가 아닙니다. [PIE 유지보수 계약](https://github.com/php/pie/blob/1.5.x/docs/extension-maintainers.md)에 패키지 메타데이터와 빌드 동작이 정의되어 있습니다.
